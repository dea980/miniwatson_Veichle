# 배포 결정 — 리버스 프록시: Caddy vs Nginx (왜 Caddy)

## 1. 애초에 리버스 프록시가 왜 필요한가

프론트가 **HTTPS**(예: Vercel)인데 백엔드(Spring, `:8080`)가 **HTTP**면 브라우저가 **mixed content**로 차단한다. 그래서 백엔드 앞에 **TLS를 종단(terminate)하는 리버스 프록시**를 둬서:
- `https://api.도메인` → 내부 `http://localhost:8080` 프록시
- Let's Encrypt 인증서로 HTTPS 제공
- (선택) 헤더·CORS·gzip·rate limit

> **주의**: 프론트를 Vercel에 두고 Next.js `rewrites()`로 `/api`를 프록시하면 브라우저는 Vercel(https)만 보므로 **리버스 프록시가 아예 불필요**할 수 있다(백엔드 http여도 됨). 단 Vercel 프록시 타임아웃(느린 RAG)에 주의. 리버스 프록시는 "브라우저가 백엔드를 **직접** 호출"하는 구성에서만 필요.

## 2. Caddy vs Nginx — 차이

| 항목 | **Caddy** | **Nginx** |
|---|---|---|
| **HTTPS(TLS)** | **자동** — Let's Encrypt/ZeroSSL 발급·**자동 갱신**을 기본 내장. 설정 0 | **수동** — certbot 등 별도 도구로 발급·갱신 크론 구성 |
| **설정** | `Caddyfile` 1~2줄, 사람이 읽기 쉬움 | `nginx.conf` 장황, 러닝커브 있음 |
| **기본값** | 보안 기본값(HTTPS·HSTS·HTTP/2·HTTP/3) 자동 | 직접 켜야 함(HTTP/3는 별도 빌드) |
| **바이너리** | Go 단일 정적 바이너리, 의존성 0 | 시스템 패키지/모듈, 성숙한 생태계 |
| **성능** | 대부분 워크로드에 충분 | 극한 처리량·초저지연에서 우위, 미세 튜닝 폭 큼 |
| **유연성** | 흔한 케이스 간단, 복잡 라우팅은 상대적으로 제한 | 복잡 라우팅·로드밸런싱·캐싱·모듈 방대 |
| **생태계** | 작지만 충분 | 업계 표준, 자료·모듈 압도적 |

한 줄 요약: **Caddy = "자동 HTTPS로 운영 부담 최소", Nginx = "성숙·고성능·세밀 제어".**

## 3. 왜 이 프로젝트는 Caddy

**맥락**: Oracle Always Free **단일 박스** + 포트폴리오/데모 + **1인 유지보수** + 트래픽 미미.

- **자동 HTTPS가 결정타** — Nginx의 가장 큰 잡일(certbot 발급·갱신·만료 대응)을 통째로 없앤다. 1인 운영에서 이 잡일이 실제 시간 싱크.
- **Caddyfile 1~2줄** vs Nginx 장황한 conf + 별도 certbot 세팅. 배포 표면(surface)이 작아 실수·유지보수 리스크↓.
- **이 규모에선 Nginx의 강점(극한 처리량·세밀 제어)이 불필요** → 그 대가로 오는 수동 TLS·복잡 설정은 순수 오버헤드.
- 보안 기본값(HTTPS·HTTP/2/3)이 자동이라 "안전한 기본"을 공짜로 얻음.

**즉 "최소 운영 표면"을 최적화한 선택.** 도구의 파워가 아니라 *이 배포의 제약(1인·단일박스·데모)*에 맞춘 결정.

## 4. 언제 Nginx가 맞나 (반대 케이스)

- 대규모 트래픽·극한 성능 튜닝이 필요할 때
- 복잡한 라우팅/로드밸런싱/캐싱/특정 모듈이 필요할 때
- 이미 Nginx 인프라·팀 전문성이 있을 때 (일관성)

→ 프로덕션 스케일로 가면 Nginx(또는 클라우드 LB) 재검토가 합리적. **이 프로젝트는 그 단계가 아님.**

## 5. 결론

- **이 배포(단일 박스, 브라우저→백엔드 직접 호출 구성)**: **Caddy**. Caddyfile 예:
  ```
  api.내도메인.com {
      reverse_proxy localhost:8080
  }
  ```
  (도메인 필요 — 없으면 DuckDNS 등 무료 도메인. 인증서는 Caddy가 자동.)
- **프론트를 Vercel에 두고 `/api`를 프록시**하면 리버스 프록시 자체가 불필요(가장 간단) — 단 Vercel 프록시 타임아웃 주의. 실행 경로는 [RUNBOOK.md](RUNBOOK.md)·[DEPLOY-ORACLE.md](DEPLOY-ORACLE.md).

**면접 한 줄**: "리버스 프록시는 Caddy를 골랐다. 1인·단일 박스 데모라 **자동 HTTPS로 운영 부담을 없애는 게** Nginx의 세밀 제어·고성능보다 가치가 컸고, Nginx의 수동 TLS는 이 규모에선 순수 오버헤드였다. 스케일이 커지면 Nginx/클라우드 LB로 재검토한다는 기준도 함께 문서화했다."
