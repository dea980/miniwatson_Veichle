# V20 — 커넥티드카 개인화: 합성 텔레매틱스 데이터 전략 (설계)

> 상태: **설계(미구현)**. V20(차량별 정비이력 + 운전 스타일 → 예측 정비·개인화 견적, JD #2)의 **데이터 문제**를 정직하게 푸는 방법. 로드맵 항목은 [AS-OPERATIONS.md §10](AS-OPERATIONS.md), README 로드맵 V20.

## 1. 문제 — 실데이터가 막혀 있다

운전 스타일 추론에 필요한 **텔레매틱스/ECU 데이터(속도·급가속·급제동·주행거리)는 딜러(현대차/모비스) 독점**이라 외부에서 못 구한다. 정비/클레임 이력만으론 고장 패턴은 봐도 **운전 스타일은 직접 추론 불가**. → 데모는 **합성 데이터**가 필요하다.

**핵심 원칙**: 합성이 "난수"면 "그거 그냥 랜덤이잖아요"에 무너진다. 그래서 **공개 자연주행(naturalistic driving) 연구의 실측 분포에 파라미터를 앵커링**하고, **모든 가정에 출처를 단다.** 신뢰는 "데이터가 진짜다"가 아니라 **"생성 파라미터가 실측에 근거하고 검증됐다"**에서 나온다.

## 2. 실데이터 앵커 (문헌에서 가져올 값)

| 신호 | 분포/지표 | 앵커 근거 |
|---|---|---|
| 급감속(HB)·급가속(HA) | **100km당 이벤트 수** (표준 지표). 온건↓ 공격적↑ | 아테네 314-driver 스마트폰 연구; 상용 354-driver(287,511 trips / 8.1M km) |
| 주행 거리(trip distance) | **log-normal** | 텔레매틱스 문헌 정설 |
| 과속률 | 제한속도 대비 초과 비율(%) | 자연주행 연구 |
| 연 주행거리 | ≈15,000 km 중심 + 분산 | 공개 통계 |
| 상관 구조 | HB·HA·과속이 **함께** 높음(독립 아님) | 운전자별 **잠재 스타일** 변수로 표현 |

## 3. 생성기 설계 (`ml/data/gen_telematics.py`, 예정)

```
차량별 잠재 스타일 s ~ Beta(α,β)         # 0(온건)~1(공격적), 인구 분포에 맞춰
   ↓  (문헌 평균·분산으로 파생, 난수 아님)
HB_rate  = base_hb  * (1 + k_hb * s)      # 100km당, 근거 주석
HA_rate  = base_ha  * (1 + k_ha * s)
overspeed% = base_os + k_os * s
annual_km  ~ 파생 분포
trip 거리  ~ LogNormal(μ, σ)              # 문헌값
   ↓
이벤트 로그(차량·트립 단위) 생성 + 요약 피처
```

- 각 상수(`base_*`, `k_*`, `μ,σ`)에 **출처 주석**을 단다: `# HB 100km당 근거: Athens 314-driver study (…)`.
- 시드 고정으로 재현 가능.

## 4. 검증 — "합성이 실측과 겹치나"

- 공개 데이터셋(Kaggle telematics / UAH-DriveSet 등)의 **요약 통계·히스토그램과 대조**해 합성 분포가 실측 범위와 겹치는지 그림으로 보인다.
- "겹침"을 캡처해 문서/데모에 넣으면 "난수 아님"의 시각적 증거가 된다.

## 5. 스타일 → 정비 → 개인화 (근사)

```
잠재 스타일 s → 부품 마모 가속 계수(브레이크·타이어·구동계) → 예측 정비 시점 앞당김
             → 개인화 견적 가중(마모 빠른 부품 우선 점검·교체 제안)
```
- 마모 계수는 **제조사 정비 주기 / UBI(사용기반보험) 액추어리 모델**에서 인용하되 **"근사"** 로 표기(정확한 인과 아님).

## 6. 앱 통합 (최소)
- 케이스/차량에 **운전 스타일 배지**(온건/보통/공격적) + **예측 정비 알림**(가속 마모 부품).
- "개인화 진단" 미니 패널: 스타일 + 마모 예측 + 맞춤 견적 가중.

## 7. 면접 프레이밍 (핵심 카드)

> "텔레매틱스는 딜러 독점이라 못 구해서, **공개 자연주행 연구의 급감속·급가속 이벤트율(100km당)·주행거리 log-normal 분포에 파라미터를 맞춘 합성 생성기**를 만들고 모든 가정에 출처를 달았다. 합성 분포가 공개 데이터셋 요약통계와 겹치는지 검증했고, 실데이터가 붙으면 **생성기만 빼면** 나머지 파이프라인(스타일 추론→예측 정비→개인화 견적)은 그대로 동작한다."

= "데이터가 없을 때 엔지니어가 어떻게 하는가"를 보여주는 강점.

## 8. 정직한 한계
- 합성은 실제 인과(도로·날씨·교통)까진 못 담는다 — 분포는 맞춰도 조건부 상관은 근사.
- 스타일→마모 매핑도 계수 인용일 뿐 실증 아님. "PoC 파이프라인 실증"이지 "정확한 예측"이 아니라고 명시.
- 개인정보/주권: 실 텔레매틱스는 강한 프라이버시·데이터 주권 이슈 — 프로덕션은 온프렘/딜러 게이트웨이 전제.
